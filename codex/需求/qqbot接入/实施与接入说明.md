## 模块与数据流

- `gateway/qqbot_config.py`：独立可选配置，默认关闭，启用时核验账号／主人／角色绑定。
- `gateway/qqbot_transport.py`：OneBot v11 反向 WebSocket，握手鉴权、登录号核验、心跳和 echo 回执匹配。
- `gateway/qqbot.py`：私聊合并、顺序生成、主人控制、主动检查和队列投递。
- `gateway/qqbot_settings.py`：配置页双开关、本地原子保存与运行器动态启停；账号和令牌仍只在部署环境。
- `gateway/qqbot_store.py`：SQLite 持久化 inbox、outbox、近期对话、调度状态、记忆同步进度及单写者租约。
- `gateway/qqbot_model.py`：复用网关当前聊天模型配置与 `build_context`；明确禁用 Eventide 和全局近期对话任务，只带 QQ 本会话历史。
- `gateway/qqbot_stickers.py`：读取本地图片／GIF目录，向模型只暴露编号、含义和标签，发送时使用图片内容快照。
- `gateway/qqbot_memory.py`：将真实用户输入与协议端确认的机器人回复幂等同步至现有 `chat_messages`，后续由现有连续感／反刍总结、审核和召回链消费。

收到的文字直接进入本地持久化会话与本轮模型输入。长期记忆不可用时，私聊仍可依赖当前输入和本地历史。未确认的回复草稿不会成为已发出的 assistant 记录。内部主动检查提示只发给模型，不写作 user 原文。

远端原文导出运行在独立后台任务中，不阻塞接收、生成与投递。按本地原文ID顺序导出，前一条失败／退避时后续记录等待，防止既有摘要按远端ID消费时乱序。每批最多20条；`QQBOT_EXPORT_TIMEOUT` 默认15秒。超时的同步RPC可能仍在底层运行，因此保留同一个在途任务，完成前不启动新的重试或后续行，避免积压线程；等待结束后仍用原幂等键确认结果。

手机客户端聊天默认路径保持原样；新增 `build_context` 关键字开关只供 QQ 禁用情感状态和全局近期原文。原来的记忆总结审核策略和退休的旧主动消息链不恢复。

## 存储与运行约束

工程采用“本地持久化收发账本 + 既有 Supabase 长期记忆”的分工，方便服务器尚未确定时完整离线测试，不需要新建云端 QQ 消息表。

- 必须持久挂载 `QQBOT_STORE_PATH` 所在目录；迁移服务器时停掉旧实例后复制整个账本（或使用 SQLite 安全备份），不能重新创建空账本冒充原实例恢复。
- 仅在用户明确允许放弃旧账本时才可重建。新账本首次绑定时持久生成独立 `export_namespace`，旧账本升级保持旧键；重启、复制和失败重试不更换命名空间。损坏时恢复备份，不删除远端消息／回执绕过冲突；原账本和替代账本不得同时运行同一机器人。
- 一个机器人使用一个网关 worker／主动运行实例。共享同一账本的多进程由租约保护，但不支持不同主机各持一份账本同时登录同一机器人。后续做多机扩展需先设计共享账本。
- 本地账本绑定机器人QQ、主人QQ和角色，不能直接换身份复用原文件。
- 用户输入按平台消息ID去重；同一批回复和发送任务持久化防重；发送前标为 in_flight，重启后转为 unknown，不自动重发。
- 回复任务保存所属输入批次关联。账本保留真实到达顺序，给模型组装时按“已完成历史＋本批全部输入”，避免生成期间收到的新问题被排到旧答案前。旧账本会原位补充认领字段和关联表，并按既有任务键回填关联；升级时先停旧进程，不删除原账本。
- 批次临时读取／入队失败或生成取消时释放认领；若数据库故障导致释放也失败，恢复后的下一轮会重新认领未提交批次。有已提交outbox的输入不会重新生成或投递。
- 只有有效 OneBot 成功回执及真实 message_id 才标 confirmed；这只说明协议端确认，不说明主人已读。
- 获得confirmed／failed／unknown或明确未提交queued结果后，先缓存首次结果并独立写入本地send_receipts。随后以同一事务补齐outbox、assistant历史和主动频率状态并删除日志；失败时保留回执，只重试本地补记，不重复网络动作。明确未提交queued补记成功后，才能按原有效期进行首次实际投递。
- 补记在发送循环检查在线状态之前运行，离线也可恢复。重启／租约恢复先应用回执；尚未补记的已知结果不会被降为unknown。结果的观察时间、日期和主动额度只结算一次；补记晚于主人回应时保留未回复计数重置。旧账本自动补充本地日志表，无新增生产迁移。
- 动作超时覆盖等待写锁、socket写入和回执的总时长。等待写锁超时且尚未写入可重试；开始写入后超时记unknown并结束连接，等待重连，不能自动重发。
- 终结的发送任务清除图片 Base64，只保留结果／正文含义；排队中保留内容快照，以免素材文件变化导致投递内容漂移。
- 本地原文与收发元数据目前随账本保留，属于私人数据；文件、备份和素材目录不要公开提交。生产留存期限尚未确认。
- 已落盘回执支持跨重启恢复；若整个本地存储持续不可写，只能由当前进程暂存，未落盘即被强制终止时仍视为结果不明且不自动重发。
- 主人输入会使尚未发送的主动问候失效。暂停／当日静默会取消本计划的待发主动任务，不能撤回已提交或已确认的消息。
- 主人控制指令的输入、状态变化和确认回复在同一事务提交，重启不会把已接受的暂停指令重新交给模型猜测处理。主人新消息会取消尚在生成的主动消息，让正常私聊先处理。
- 主动任务持久保存生成时的状态修订号。未提交结果补记恢复、认领待发任务、OneBot获取写锁后准备真正写出，均会重新检查资格；旧问候不能借恢复、重启、暂停后恢复或新输入处理完成重新变有效。失效即终结并清理图片载荷，控制确认和普通回复继续发送。
- 恢复资格用当前时间判断过期；真正写出前同时检查最新开关、时段、安静期和每日次数／冷却。confirmed／unknown已提交结果仍如实补记，不因后来暂停而撤销历史或重发。旧账本补充eligibility_revision；没有可恢复版本的旧未提交主动任务保守取消，不影响普通回复和已提交记录。

## 配置

配置示例位于 `qqbot/config.env.example`。它是合并参考，不要覆盖已有 `.env`。真实账号、Token、主提示词和图片应放部署环境／被忽略的私人目录。

最少需要 QQBOT_TOKEN、QQBOT_ACCOUNT_ID、QQBOT_OWNER_ID、QQBOT_ASSISTANT_ID；Token 至少24个非空白ASCII字符。角色必须是现有手机角色，若 MEMORY_ASSISTANT_ID 非空，两者必须一致。配置完成后可在配置页开启QQBot总开关。

QQBOT_SYSTEM_PROMPT_FILE 可提供私有主提示词，数据库活跃人格仍从现有上下文加载。不设置时使用通用 QQ 私聊主提示词加数据库人格；如果手机端还有额外完整设定，应在实际接入时核对并提供，不默认抓取手机客户端配置。

主动消息另需打开独立开关，并显式填写 QQBOT_TIMEZONE、QQBOT_ACTIVE_START、QQBOT_ACTIVE_END。

### 配置页双开关

配置页的“QQBot”卡片提供总开关、主动消息开关及当前连接状态。账号／令牌／角色不完整时无法启用总开关；时区或时段不完整时无法启用主动消息。保存失败不伪造成功，响应丢失时回读当前状态；读取失败显示未知并禁止修改。

两个开关默认关闭，保存即生效。总开关关闭会断开QQ连接、停止QQ消息任务并关闭主动消息；单独关闭主动消息仍保留私聊。关闭／重新开启会取消旧主动问候，重启或延迟取得运行租约也不补发旧问候；已提交的confirmed／unknown仍如实结算。QQ里设置的暂停／今天静默独立保留，前端开启不解除它们。

`GET /admin/api/qqbot/settings`读取设置、准备情况和运行状态；`PUT`接受非空布尔字段`enabled`和／或`proactive_enabled`。沿用网关Token鉴权并禁止缓存，不返回账号、密钥、聊天、服务器路径。状态中`enabled`表示保存的选择，`running`／`connected`表示实际运行／连接情况；启动失败会明确显示，仍可关闭。

设置原子保存在`QQBOT_SETTINGS_PATH`，默认`data/qqbot-settings.json`；只存两个布尔值。没有文件时才采用`QQBOT_ENABLED`和`QQBOT_PROACTIVE_ENABLED`环境变量；保存后以文件为准，修改环境变量不能覆盖已保存选择。文件已加入忽略列表，迁移服务器时须一并保留并持久挂载其目录；一个机器人仍只用一个网关worker。账号、令牌等继续通过环境配置，变更后重启网关。

开关文件损坏或不可读时关闭QQ且禁止保存，不回退到可能开启的环境变量；修复文件后重启。写入失败保留旧文件与当前运行状态；保存成功而运行切换失败时显示错误及实际状态，可关闭后重试。未启用时不创建QQ账本、连接或消息后台任务，管理配置读取正常可用。此开关不新增生产SQL，原记忆桥迁移仍须部署前落实。

本地测试预览使用`node tools/preview_qqbot.cjs 8001`，打开`http://127.0.0.1:8001/admin/index.html#/config`。预览仅用合成状态、进程内保存，不读取部署环境或连接QQ／数据库；真实持久化与运行控制由隔离后端测试验证。

示例中的检查间隔300秒、聊天后安静1800秒、主动消息间隔3600秒、每天最多3条是可修改的工程默认值，不代表用户已经确认真实发送频率。检查到期也不等于一定发送；模型可静默。未回应的主动消息逐次延长间隔，收到主人QQ新消息后重置未回应计数。次数按实际 confirmed／unknown 的主动投递计算，不把普通回复算进主动限额。

上述主动消息节奏与表情使用完全分开。表情没有轮数间隔、没有同图时间冷却，可以连续重复。自动每轮最多一张，主人明确要求多张时最多处理10个目录编号（资源边界）。

## 表情素材

2026-10-22用户提供168张猫咪素材（144 GIF、24 PNG），已完成逐图描述／标签、原图哈希及全部发送载荷核验。生产清单`/data/qqbot/stickers/cloud-cat-v1/manifest.json`已配置并加载168项；用户确认“收到动图且正常播放”，真实动图验收通过。私人整理包为`qqbot/private/stickers/cloud-cat-v1.zip`，素材未提交Git。详见[生产加载与验收](../../代码修改日志/qqbot接入/猫咪表情云端加载-26.10.22.13.00.md)。下方“未提供”保留初始阶段说明。

`qqbot/stickers.example.json` 是合法空目录。未配置素材时可以文字聊天；真实素材由用户后续提供，没有生成或抓取替代图片。

目录文件缺失／不可读时使用空目录；单张素材缺失／不可读时记录警告并排除该项，其他素材和文字服务继续工作。路径越界、重复ID及非法目录结构仍明确拒绝，不能借缺失素材跳过安全校验。

推荐把实际目录和素材放入被忽略的 `qqbot/private/`。目录形如：

```json
{
  "version": 1,
  "stickers": [
    {"id": "cat_shocked", "file": "cat-shocked.gif", "description": "猫猫震惊", "tags": ["震惊", "接梗"]}
  ]
}
```

file 是相对目录文件的位置，只能在该目录内；支持PNG、JPEG、GIF、WebP，每张最多8MiB，最多200项。编号唯一，模型只能选择现有编号；它不能指定任意本地路径或外网URL。图片内容随 OneBot 图片消息发送，因此网关和 NapCat 不要求共享文件路径。

## 服务器接入顺序（初始本地阶段清单）

1. 新服务器准备网关和独立 NapCat 服务，配置账本、开关文件与素材持久卷；确认保存的总开关关闭，没有文件时保持 QQBOT_ENABLED=false。
2. 核对现有 chat_messages 表、角色ID与服务端 Supabase 凭据。
3. 执行并核验 `supabase/migrations/20261021010000_qqbot_chat_export.sql`，确认 `qqbot_publish_chat_message` 仅 service_role 可调用且 PostgREST 已刷新。
4. 配置QQ账号和主人、独立Token、角色、所需主提示词／表情目录，然后在配置页开启总开关；没有设置文件时也可用环境变量作为首次启用值。
5. NapCat 设置 WebSocket 客户端（反向WS）、Universal连接、数组消息格式，连接网关 `/qqbot/onebot`，发送匹配的 Bearer Token 和 X-Self-ID；公网使用wss。
6. 登录小号，先验收私聊真实回执、重复事件、断线和图片／GIF，再配置并启用主动消息时段与频率。

连接已鉴权但登录号核验未完成时，最多暂存64条／256KiB的主人私聊事件。核验成功后按顺序重新交给持久入口；核验失败清空，超过上限则断开，不把未核验事件交给模型。

以上是初始本地阶段的接入清单。网关代码不自动安装或登录 NapCat，也不修改 QQ 资料；本机安装及扫码由后续授权完成。原生产桥接迁移已于 10 月 22 日执行并核验，本次沿用同一 Supabase，已再次核验 RPC 及权限，没有新的生产 SQL。

## 查询与主人控制

- `GET /admin/api/qqbot/status`：沿用网关Token，仅返回启用／连接／主动开关、暂停状态、发送状态计数和表情数量，不返回QQ号、Token、图片、聊天正文或服务器路径。
- `暂停主动消息`／`恢复主动消息`／`今天先别找我`／`查看主动消息状态`；也支持 `/主动消息 暂停`、`/主动消息 恢复`、`/主动消息 状态`。
- 命令只识别主人本次私聊的明确完整表达，不把“不要暂停主动消息”“他说暂停主动消息”作为控制指令。
- 首期没有业务工具执行循环，模型的 tool_calls 不执行；QQ 内待办／搜索／MCP工具属于后续扩展。
