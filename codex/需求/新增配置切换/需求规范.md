## 1. 目标与范围

在现有控制台增加模型服务配置管理，使用户能够添加供应商、API Key 和模型名称，并按不同用途手动选择要使用的配置。供应商配置全局共享，各用途分别设置。

第一批只管理模型服务的配置。文本模型支持添加与手动切换；向量模型单独分类，仅提供只读查看入口。

本需求来源为本次聊天中用户明确提出的页面布局、共享配置、独立设置、多 Key 和向量模型只读要求。此前对其他仓库的调研仅供后续实现参考，不作为自动扩大本批范围的依据。

## 2. 配置页面与布局

1. 保留侧栏“配置”入口，在当前配置页面内增加两个横向页签：**常规配置**、**API配置**。
2. 用户截图中页眉分隔线下、现有内容上方的蓝框附近，作为页签位置参考；沿用控制台已有视觉风格与页面切换方式。
3. 当前运行状态、功能开关等内容归入“常规配置”；模型服务的供应商、Key、模型选择与用途配置集中放在“API配置”。
4. API 配置采用类似待办列表的横向条目布局，每个用途占一整行，便于查看当前配置并进行调整。
5. 条目清楚展示用途、当前供应商、Key 别名或脱敏标识、模型名称及配置调整入口。
6. 向量模型在 API 配置中单独分类，明确标注本批为只读。

## 3. 全局共享的供应商配置

1. 供应商只需添加一次，在各处模型服务配置入口均能看到同一份供应商库，不按页面重复添加。
2. 供应商配置包括名称、API 地址（Base URL）、API Key 和可用模型名称。
3. 一个供应商可以保存多把 API Key；每把 Key 可以设置别名，便于在不同用途里区分和选择。
4. 一个供应商可以维护多个模型名称，配置用途时可以从中选择。模型名称在供应商表单内逐项添加、编辑和删除，每项独立输入框，提供“添加模型”及逐项移除入口，不再要求每行一个地填写多行文本；保存供应商时统一生效。
5. 不同用途可以复用同一个供应商、同一把 Key 或同一个模型，也可以各自选择不同组合。
6. 全局共享的是供应商、Key 和模型候选配置；各用途的当前选择分别保存。切换某个用途，不应将其他用途同时改成相同配置。
7. 添加供应商或 Key 不等于立即替换各用途现有的生效配置。
8. 向量分类的全局可见性遵守第 6 节只读边界，不能因共享配置而开放向量服务切换。

## 4. 按用途分别设置

用户已明确选择日常聊天、QQ、光遇提供分别设置的入口，不强制共用一个模型选择。

| 用途 | 第一批要求 |
| --- | --- |
| 日常聊天（手机客户端／通用聊天入口） | 可独立选择供应商、Key 和模型。 |
| QQ 模型服务 | 提供独立设置入口，可选择供应商、Key 和模型。 |
| 光遇模型服务 | 提供独立设置入口，可选择供应商、Key 和模型。 |
| 记忆总结，包括现有连续感总结等文本模型用途 | 按现有用途提供配置调整入口，可选择供应商、Key 和模型。 |
| 反刍 | 提供独立配置调整入口，可选择供应商、Key 和模型。 |
| 其他现有文本模型服务用途 | 纳入对应用途的配置管理，不能只覆盖聊天而遗漏仍在使用的模型 Key。 |
| 向量模型／Embedding | 单独分类，仅查看当前配置，不能切换。 |

盘点既有模型调用时，以现有实际业务用途为准；增加配置入口不等于新增模型业务功能。

## 5. 各功能页面的配置调整入口

1. 在涉及文本模型 API Key 的相关功能页面或区域增加“调整 API 配置”等清晰入口，例如记忆总结、反刍及聊天相关配置区域。
2. 各入口访问同一套全局供应商库，调整的是对应用途的配置。
3. “API配置”页可集中查看和管理各用途的当前选择；从其他页面进入调整时，应清楚识别当前调整的用途。
4. 不在不同页面维护互不相通的供应商、Key 或模型副本。
5. 现有配置页尚未接入的“更换配置”入口应纳入本批配置管理流程。
6. 具体使用原地弹窗、抽屉或定位到对应配置项等展示方式，属于后续交互设计细节；本次未单独指定必须采用某一种形式。

## 6. 向量模型：第一批只读

这是用户在了解向量模型更换可能涉及历史向量重建后，明确确定的第一批边界。

1. 提供独立的向量模型查看入口，展示实际生效的供应商／API 地址、模型名称、向量维度及 Key 别名或脱敏标识等已有配置状态。
2. 本批不能在该入口更换供应商、地址、Key、模型或维度，也不提供切换或保存变更的操作。
3. 不能通过其他共享配置入口绕过只读限制，间接改变向量服务实际使用的配置。
4. 仅增加查看能力，不改变既有向量生成与检索行为，不改写历史记忆向量。
5. 本批不做向量模型切换、历史向量重建或相关迁移；这些能力是否进入后续批次，另行确认。
6. Key 展示沿用现有默认隐藏／脱敏规则；需求文档不保存真实密钥。

## 7. 本批明确不做

- 不增加 Key 失败轮换、跨供应商自动故障切换或按请求自动轮询分配；本批由用户手动选择配置。
- 不开放向量服务配置切换，不重建历史向量。
- 不管理网关自身访问 Token、记忆插件 Token、MCP Token、待办插件 Token 或数据库访问凭证等非模型服务凭证。
- 不将供应商共享解释为所有业务用途强制使用同一套模型配置。
- 原需求归档阶段不写代码；用户后续已授权本地实现。本批仍不包含生产数据库变更、Git提交／推送或服务部署。
