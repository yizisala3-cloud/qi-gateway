# 光遇接入

本功能由 Windows 本机桥接 `tools/sky_companion/` 和网关光遇交付接口组成。长期保留以下约束：

- 默认只绑定 MuMu 编号 10、名称“MuMu安卓设备-10”、包名 `com.netease.sky`；每次截图或输入前核对当前 MuMu 信息、ADB 端口及游戏前台。实例不匹配、端口改变、分辨率改变时拒绝操作。
- ADB 端口从 `mumu-cli info --vmindex 10` 获取，不硬编码；中文使用 MuMu 官方 `input_text`，回车发送。只用 UI 输入，不读写游戏进程或游戏内存。
- 网关基地址为 `https://yiziwanguan.com`，调用 `/status`、`/v1/sky/chat/completions` 和 `/v1/sky/deliveries`。读取仓库根 `.env` 的原 `GATEWAY_TOKEN`，不把 Token 写入配置、日志、代码或文档。HTTPS 验证开启，不跟随重定向，不自动切换域名；预览路由不支持时停止，不能降级普通聊天接口。
- 现有人设和记忆继续由 qi-gateway 注入；本机只补充简短游戏聊天限制。游戏中的文字作为玩家消息，不能获得命令执行能力。
- 本机 RapidOCR CPU 推理，模型随依赖包提供。常驻 OCR 子进程、原始 RGBA 截图和分区域识别，默认 1 秒轮询；没有新消息不请求模型。模型会话 intra/inter 均为 1 线程，变更前用同一截图比较 CPU 耗时、识别延迟及文字结果，不能只凭风扇声音判断。OCR原始截图保留本机；开启视觉后将压缩的游戏截图交同一网关现有模型。回复发到当前游戏聊天频道，不具备私聊路由能力。
- 视觉由 vision.py 管理：首个新消息轮、每四个完成轮或观察超过六十秒时，在下一次有新消息后取图；模型内部 LOOK 可按需请求一张。不增加空闲模型、每轮图片上传或主动消息。配置需校验，示例默认关闭。截图与编码共用收件I/O锁，继续核对设备／前台／分辨率；最长边1280、JPEG质量75、上限500KB，使用内存数据，避免文件覆盖改变请求图片。
- 视觉预览为严格JSON对象scene/reply，只交付自然reply。scene仅含可确认观察，携带时间／过期／失败状态，不把旧画面当当前。能看清正常接话；测试中看不到／看不清如实说，不凭外观认玩家；非测试日常缺图允许简单人设想象，但不能写入scene作为事实。看图用原DeepSeek模型JSON模式、低思考强度、2048预算；无图缓存轮和LOOK决定关闭思考。拒绝空、截断、无效、额外字段、控制词及超长回复，不将思考内容当观察。日志只记结束原因、长度、用量，不记思考原文、图片数据或凭据。
- 视觉服务／编码失败保留文字交流并退避六十秒，不在同一决定无依据重复图片请求；设备／前台错误继续停止。控制词、图片、scene不进入正式对话，日常想象不能污染测试观察。模型预览、输入、发送确认和正式交付分别验证，格式有效不代表视觉事实正确。
- 本机当前 `chat_mode=group`，接收所有显示名字的玩家，`primary_user=叶子` 保留主要用户身份；其他玩家的文字和关系不能套给叶子。示例配置默认 direct，只接 `peer_names` 白名单。配置、提示词和文档须同步群聊范围。
- 坐标只写 `private/config.json`，聊天记录 ROI 排除输入框。整个 `private/` 忽略 Git，其中日志、截图及识别 JSON 可能含真实对话。
- 启动时已有文字作为基线；连续两次观察到新文字才触发。Tracker 和 Inbox 共用 message_identity，保留身份、字词、数字、运算符及 emoji，仅规范化排版和末尾纯标点颜文字；原文交模型，不可用于放宽原生输入校验或猜测玩家身份。同次运行同人同句持续去重，短暂漏读不解除；真实重发也可能不触发。本机 ID 不等于游戏原生消息 ID，重启建立新基线。
- 群聊发送者必须带实际游戏的 `正文 - 名字` 后缀及深色气泡，自己的浅色气泡不参与触发；不能仅凭正文中提到名字判断来源。direct 也先解析真实后缀，只有没有后缀时才兼容旧前缀格式；已有不允许的后缀不能靠前缀绕过。置信度不足 0.85、无名或陌生人不触发。OCR 与解析共用 layout.py：先合并同排碎片，再按文字中心距离、左对齐和深色气泡累积正文，不固定正文行数；表情／粗体引起的合理文字框重叠不应阻断，完整标签、气泡变化、明显行距或左侧不符仍是边界。横杠可在正文末尾、名字行或单独一行。末行名字受背景干扰时，用上下文、明亮字形分离及 2 倍复读，要求实际读到分隔符、位置匹配、名字一致和至少 0.85 置信度，不猜配置中的名字；原始低置信度前导“一”可被明确复读出的分隔符校正。名字行的同次清晰复读可更新正文；正文末尾分隔符另用整行识别验证时，按可见气泡边界排除外部背景，字词数字须与原文一致，正文沿用原检测结果，避免额外标点改变身份。不得用 AI 已发正文集合过滤已确认来源的玩家消息。
- 收件线程在模型生成、键盘准备和中文输入期间继续工作，截图／跟踪／入队共用 I/O 锁和同一个 Tracker。提交前持锁补读聊天 ROI，未稳定的新行再读一次；有新事件则合并，必要时只清空精确匹配、仍聚焦于本包编辑框的本程序草稿，使用带 text=expected 的原生选择器，复查空串及边界。用户编辑过的草稿不得清除。只在最终读屏／提交／回显窗口暂停收件，不能整段 send 都锁住接收线程。
- Inbox 对待处理／处理中／已处理事件均拒绝重复入队；保留跨帧已知相对顺序并稳定拓扑排序；临时OCR缺行不删约束，无证据的平局沿入队顺序，矛盾逆序不覆盖既有顺序。顺序节点10000到限停止，避免无限增长。只有当前 inflight 在完成或 PASS 后确认，后续 pending 保留。1000 条队列、5000 条去重事件到限停止，不丢队列；重启不自动重放旧事件。
- 多条消息按旧到新排列，query 带 message_order、latest_message；合为一条自然短回复，最新内容优先。旧叶子发言不能盖过新消息，但主要用户身份不变。未发送草稿作废为 superseded 并链接新决定，禁止进入历史或正式交付。每次最多两次草稿更新，之后及已提交期间的新事件进下一轮，防止持续消息造成无限生成。首次取批及合并均按实际配置序列化query的20000字符预算分批，包含尾条重复；剩余事件和ID保留。单条本身超限保存原文并标记rejected_oversize，不截断或阻塞正常消息。
- 模型完整输出 PASS（仅忽略首尾空白和大小写）时 Gateway.generate 返回 None，不发送、不加入本机 assistant 历史；新事件可使未确认的旧 PASS 作废并合并重判。普通句子含 pass 不静默。叶子分享、玩笑、短句通常回应，其余玩家按语境；本轮是否含叶子由 JSON 判定，不补答云端旧问题，不用固定限频代替判断。
- `last_reply.json` 区分 action=pass/reply、handled、sent；跳过后不能把旧 last_send 当成新发送。ask 仅预览，也要正确表示 pass。停止期间得到的决定不确认处理，留存未完成批次。
- 模型调用前按 trigger_kind=reply 和事件 ID 集合派生决定 UUID，写入 private/decisions；已有同批决定拒绝重复执行。先记录 submitting 再按唯一发送键，不明回显为 unconfirmed 并停止。交付复用该 UUID、原载荷和时间；同 ID 改正文拒绝且保留原文件。已入库交付重启可补齐决定完成状态。不同事件允许回复同句，不能按 AI 正文全局去重；主动触发来源和授权规则须以后另行实现，本次不启用。
- save_json 用同目录唯一临时文件原子替换；仅 Windows 5/32 错误最多四次替换尝试、间隔 50 毫秒，记录结构化异常。持续失败传播停止，不改权限、不扩展到游戏输入或发送重试。
- UI Automator2 3.7.1 经 ADB 绑定同一设备，关闭 waitForIdle 等待并读取原生 EditText；仅接收光遇包内唯一聚焦、可见、启用且非密码的编辑框。空串或与 hint 完整相等才视为空，真实草稿“聊天”不能被省略号归一化吞掉。输入后原生 text 必须与目标逐字一致；不能依赖透明编辑框的背景 OCR 检查草稿。
- 发送前两次读取原生编辑框的位置须一致；输入框消失或位置变化时停止。发送后确认原生草稿清空及新增自身 OCR 回显。证明区域到实际编辑框上沿，自身气泡 2 倍裁剪重读，可合并相邻拆行。只在回显阶段做全半角、弯／直引号及末尾标点归一化；明确自身气泡不少于 12 字时最多一处 OCR 编辑差异，短于 12 字严格核对；兼容无来源数据阈值仍为 16 字。原生输入始终逐字一致。
- 回执按提交后五秒期限只读轮询，不设固定三次上限，已经开始的一次 OCR 可以晚于期限完成。旧同文滚出而新同文在底部出现时结合自身来源和几何变化确认；回到同位置时必须有明确自身来源、旧前置序列消失和至少三条不同具名消息紧邻目标的整体替换证据。不能因一行 OCR 变化就认定成功。旧消息未变、只上移、其他人复述不算成功。完全无可观察变化时停止；用户不可同时滚动聊天历史。
- 生成接口只预览，不调用正式对话保存；PASS、预览、输出拒绝、停止及游戏发送失败不提交交付。确认后以 UUID 和确认时间先写本机交付文件，再请求保存。`persisted=false` 重启仅补交记录；不重复游戏发送，也不更换 UUID。服务端解析自身 assistant_id，不由客户端指定；同 UUID 改内容返回冲突。
- `supabase/migrations/20261023010000_sky_confirmed_chat_delivery.sql` 提供仅 service_role 可用的 RPC 和启用 RLS 的账本。同一事务保存 user/assistant 对话及回执，以事务锁保证并发同 UUID 幂等；对话 conversation_id 为 `sky:mumu:<vm>`，时间沿用现有 CST 存储约定。先落实兼容 SQL，再发布网关，再启动本机；不自动清理旧版错误历史。
- 发送结果不明立即停止，不自动重发。停止标记在输入前和发送前复查，不能因重启前置检查吞掉新停止请求。模型或 OCR 请求可能尚需等待超时，但结束后不得继续发送。
- 诊断、校准、单次发送和自动循环共享系统文件锁。停止命令不拿设备锁，允许随时请求停止。后台助手窗口须隐藏；用户主动双击启动脚本则显示可 Ctrl+C 的终端。
- 桌面手动入口使用指向项目内start.cmd的快捷方式，工作目录为项目根；脚本通过自身位置定位依赖。用户先打开设备10与游戏，再双击并保留启动窗口，Ctrl+C停止。快捷方式资源创建与登录自启分别管理，不能隐式注册自启。
- 当前实现文字和画面理解，不执行移动、抱抱、牵手、购买或互动动作；后续动作适配必须另行校准并验证。

修改解析、去重、设备绑定或发送状态机后，运行 `tests/test_sky_companion.py`、`tests/test_sky_companion_duplicates.py`、`tests/test_sky_companion_wrapped.py`、`tests/test_sky_companion_vision.py` 和 `tests/test_sky_companion_review_regressions.py`。换行修复需回放真实截图，覆盖发送者独占末行、分隔符漏字、背景变化及不同玩家边界，不只验证手写 OCR 夹具。交付链另跑 `tests/test_sky_delivery.py` 及相邻聊天持久化、模型路由测试；数据库原子性、重复迁移、并发幂等及权限以隔离 PostgreSQL 验证，`tests/sky_delivery_postgres.sql` 只用于隔离库。涉及 OCR 或输入变化时，还应在用户指定实例验证空草稿、真实中文草稿和新增回显，并区分模型连通、输入成功、发送确认、后台循环和正式入库结果。修改 PASS 时覆盖模型静默、后续恢复回复、并发收件、停止保护及预览，并用实际模型分别验证互聊与主要用户的短句。

正式对话隔离不等于禁用预览时的记忆检索、热度和日志行为。故障和复验状态维护在[活动清单](../../需求/光遇接入/后续待修复.md)，历史审查不改写。日常操作见 [本机说明](../../../tools/sky_companion/README.md)，实际联调和部署证据写入对应代码修改日志。

## 开关、完整身份和确定交付

- sky.enabled复用app_settings，保存enabled布尔及pause_epoch UUID对象，默认关闭。每次成功关闭必须以sky_set_access事务生成新代次，开启保留最新代次；跨进程与并发不能由Python缓存读改写代替。管理GET/PUT /admin/api/sky/settings及本机GET /v1/sky/settings鉴权、no-store，PUT仍只接受严格布尔enabled。非法／旧布尔值或缺迁移不开放生成，保存失败不假报成功。status声明sky_access_control=2，模型预览要求X-Sky-Access-Protocol: 2；新旧网关和本机版本需配套，不静默绕过代次校验。
- 模型预览在构建上下文前及返回后读取状态；期间关后再开也取消旧结果。本机收件在模型等待期间持续检查，生成／看图／PASS／输入／提交均核对本批代次；旧回合取消不得二次清掉重开后的新消息或写入旧视觉缓存。关闭暂停收件和新发送、作废未发队列，重开建立新基线。已提交后的确认及确定交付仍完成，不能把已提交决定降为未发送；只清理逐字匹配的本程序草稿。发送前强制刷新，不依赖一秒正缓存。
- 请求拒绝不代表当前开关关闭。sky_disabled／sky_generation_cancelled不得写False缓存或无条件pause_access；必须按原事件批次重读权威设置，只有真实状态／代次变化才全局暂停，其他取消限于原inflight／决定，不动pending新事件。设置读取失败保留队列并停止。SkyPaused.reset_required只请求状态协调，不授权再次清空新代次。取消决定cancelled_by_gateway不发送、不进入正式对话，也不重试原事件。
- 视觉成功accept和失败failed的代次检查、状态更新及对应诊断必须共用io_lock；失败路径还在锁内取得文字上下文快照。网络生成在锁外，不能把长请求放进游戏I/O锁；暂停清空后的新VisionState不得接受旧摘要或旧退避。修改此边界回归test_sky_cancellation_order.py及原双线程独立复现，覆盖文字／图片／LOOK旧请求迟到、新消息实际确认交付、状态读取失败和旧失败退避。
- 名字使用name_key保留标点和全半角等价；不能用正文normal去掉姓名末尾点号。标签分隔优先真实空白横杠边界，姓名内部符号保留，多个同等候选拒绝识别。OCR同排／局部重读／多行拼接必须保留synthetic_spaces来源，不把程序插入空格当实测边界；独立姓名行等明确几何证据用sender_separator保留完整名字。direct与群聊主要用户权重同步此规则。
- 发送确认后先持久化outbox及含原UUID／正文／confirmed_at的决定，再写辅助截图和JSON。辅助诊断失败仅记结构化异常，不改变确定事实。两份确定记录只有一份成功时，启动能据其恢复并仅补交记录；未确认决定不能自行升级。两份都无法落盘仍停止，不重发。
- 新幂等迁移20261024010000_sky_retry_original_author.sql在原消息归属下校验旧哈希，不重写历史回执或对话；新验证信封跨进程由数据库保证幂等，不能只依赖Python对象复用。实际客户端内容变化继续409，权限／事务／并发约束保持。先迁移再发布，不把本地验证当生产生效。
- 开关依赖20261024030000_sky_access_pause_epoch.sql及已有app_settings，旧布尔值转换保留开关；迁移重复执行不得重置对象／代次。RPC只授权service_role，关闭与代次必须同事务；先补交迁移再暂停迁移，再发配套代码。新回归test_sky_pause_epoch.py和test_sky_pause_pgserver.py --db覆盖快速ABA、恢复收件、PASS／LOOK／已提交保护以及真实事务、并发、重启和权限。
- 修改上述流程增加tests/test_sky_companion_five_fixes.py、test_sky_settings.py、test_sky_config_frontend.py回归；真实数据库用test_sky_delivery_pgserver.py --db，只连接一次性隔离实例。前端验证保存中重复、失败和不明结果回读、跨访问晚到响应，并保留真实浏览器效果。用户明确暂不实机时尊重限制，记录未验收项。
