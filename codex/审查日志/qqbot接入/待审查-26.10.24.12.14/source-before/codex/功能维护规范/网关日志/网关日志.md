## 稳定约束（勿改）

1. **主记录者仲裁**：logging handler 是唯一主记录者。中间件只在
   「响应 ≥500 且本请求 `error_events == 0` 且未被显式抑制」时补边界
   兜底事件——WARNING 不抑制兜底（BUG-03），只有 ERROR+ 级别事件算
   「终结性错误已记录」；未处理异常按 `id(exc)` 身份去重（端点已
   `log.exception` 后 re-raise 的同一异常不双计）；日志查询链自身失败
   调用 `suppress_boundary_for_current_request()` 抑制本请求兜底
   （BUG-12）。`track_task` 的 done callback 只记协程内未捕获异常。
   任何新代码不得在同一故障上既 `log.exception` 又 `emit_error`
   （会双计数）。
2. **排除名单**：`gateway.log_store` / `gateway.log_internal` /
   `logging_events` 自身、`uvicorn.*`、`asyncio` 不进采集（防递归与
   ASGI 异常双计）。writer 自身诊断必须走 `gateway.log_internal`；
   writer 线程内另有线程本地 `suppress_capture()`——写入/重试/清理链
   调用公共 `db.get_client` 产生的日志不重新采集（BUG-11），业务线程
   不受影响。采集排除 uvicorn 与**平台输出清洗**互不排斥（BUG-25）：
   `_PlatformScrubFilter` 必须同时挂在 root 既有 handler 与
   `uvicorn` / `uvicorn.error` / `uvicorn.access` 命名 logger 的独立
   handler 上（默认 LOGGING_CONFIG 下它们 `propagate=False`，不经
   root）；安装/卸载经 `_platform_scrub_targets()` 幂等增删。
3. **emit 零 I/O**：`GatewayLogHandler.emit` 只做格式化、脱敏、入队；
   任何网络/磁盘操作只允许出现在 writer 线程。
4. **先脱敏后入队 / 出口同规则**：所有持久化介质（表、spool、平台
   输出）与**错误响应 / 业务失败记录出口**使用同一清洗（BUG-26/27）：
   `logging_events.scrub_error_text(text, limit)` 是聊天/SSE/管理错误
   出口与 `memory_digest_runs` 失败字段（`error_message` /
   `model_output_excerpt`）入库前、`_public_run` 读取投影的统一入口
   （旧敏感样本展示层保护，不改写库内历史）；管理通用 500 用固定中文
   摘要，详情走日志链。截断不能替代脱敏。`safe_context` 只收白名单键
   （`_SAFE_CONTEXT_KEYS`），未知键拒绝；正文/密钥永不入库。清洗包含：
   格式正则（Bearer/JWT/sk-/URL userinfo 等）+ **已配置密钥的实际值
   掩码**（`_configured_secret_values`，含 `GATEWAY_KEY_REF_SECRET`，
   所有非空值无长度豁免，BUG-01）+ 数据库回显移除（BUG-02：括号形态
   `Failing row contains (…)` / `Key (…)=(…)` 按**配对扫描**整段移除
   ——嵌套括号按深度、右括号需后随句子终点、未闭合 fail-closed 到帧
   边界；引号形态 22P02 / malformed array literal 按**受限贪婪**匹配到
   帧边界内最后一个引号，值可跨行可内嵌引号，调用帧保留）；结构化
   SDK 异常（APIError 等 code+message 形态）格式化时只保留 code +
   message 模板行（`_scrubbed_exception`，DETAILS/HINT 整段移除）。
   平台输出经 `_PlatformScrubFilter` 获得同一清洗：**过滤器绝不替换
   `record.exc_info` 的异常对象**（异常身份是 `id(exc)` 去重契约，
   BUG-20），只重算覆盖 `record.exc_text` 缓存与消息文本。脱敏异常
   副本必须递归保留 `__cause__` / `__context__` / `__suppress_context__`
   / `__traceback__`，并覆盖 **`BaseExceptionGroup` 子异常**（逐个
   脱敏后重建，构造失败退回基类）；循环链 / 深度 ≥8 / 克隆失败一律
   **安全占位**（`<类型名: 说明>`），绝不返回原对象（BUG-21）；原异常
   对象绝不修改。
5. **幂等**：事件 `event_id`（uuid）由采集时生成，重试复用同一 ID；
   写入用 `upsert(on_conflict="event_id", ignore_duplicates=True)`。
   改动写入路径时不得引入重复计数。
6. **有界**：队列（默认 2000，满时优先保留高等级并计 dropped）、内存
   重试（默认 500 **事件数**，按事件数严格执行含 0 与单批过大——级别
   优先、同级取新裁剪，BUG-23）、spool（文件数/字节数上限；**写入前
   预留额度**——`write()` 先按「文件数+1+批字节」腾挪，删除失败拒绝
   本批不创建超额文件，调用方按 `spool_write_failed` 准确计损，单批
   超字节上限直接拒绝，BUG-22）、关闭 flush（默认 5s）全部有界；任何
   改动不得引入无限内存或无限阻塞。
7. **业务隔离**：日志写入与业务事务完全分离；日志故障只影响日志
   （退避、降级、丢弃计数），绝不阻塞业务请求或网关关闭。
8. **RPC 契约**：五个函数（`gateway_log_query/event/group/facets/
   cleanup`）security invoker、固定 `search_path = public`、固定
   `timezone = 'UTC'`（JSON 时间戳不随会话时区漂移）、只授予
   service_role；表 RLS 启用且无策略。清理用 advisory **xact** 锁
   （事务级自动释放，勿改会话级）。`gateway_log_query` 分页为
   **「快照 + 可见性快照 + 已看集合」**（BUG-05）：`p_snapshot`（入库
   时间上限）+ `p_visible`（pg_snapshot 文本，第一页由 RPC 在同一事务
   内经 `pg_current_snapshot()` 取回并随 JSON `visible_snapshot` 返回）
   + `p_seen`（已看 fingerprint 逗号列表）——表列 `commit_xid xid8
   default pg_current_xact_id()` 为插入事务 64 位 ID，
   `pg_visible_in_snapshot` 判定会话可见性：已看组聚合会话内冻结
   （晚提交行不并入），快照时刻整组不可见的晚提交组按排序位置落入
   后续页（不漏组），快照后入库事件不进入会话。cursor 为三段式
   `snapshot|visible|fp,fp,…`（API 校验格式与 1000 上限）随翻页回传；
   前端回看已翻过的页复用会话页缓存（不发请求、快照与冻结区间不变），
   仅刷新/筛选变更重建会话，`visibleSnapshot` 随详情请求回传。
   `gateway_log_group` 复用列表的 level/module/search/key_ref/
   snapshot/visible 筛选（BUG-06）；列表投影不含 message_raw/
   stack_trace 大字段（BUG-16）；`gateway_log_event` 投影排除内部
   `commit_xid`。TASK-02：`p_key_ref` 按完整密钥标识筛选，组投影与
   样本携带 `key_ref`/`credential_role`/`provider`，facets 返回
   `keys` 选项。
9. **spool 保留期**：本地 spool 与数据库 cleanup 共用
   `GATEWAY_LOG_RETENTION_DAYS`——有效文件按行内真实 `occurred_at`
   过滤重写（重写失败保留下轮重试、计数不虚增）、损坏隔离文件按
   mtime TTL、`replay` 恢复前过滤过期事件（仅文件实际移除后计数）；
   writer 周期顶部小时级调度执行，退避期内照常、不依赖数据库成功
   （BUG-24）。损坏损失状态用累计口径（`corrupt_total` /
   `corrupt_purged_total` / 当前 `corrupt_files` 分列），当前隔离数
   归零不清除历史损失提示（BUG-15）。
10. **页面生命周期**：日志页详情弹窗与 AbortController 登记
   `detailSessions`——unmount 关闭弹窗、取消在途请求并失效晚到回调；
   用户关闭同样清理（BUG-07）。业务捕获点降级记录必须传 `exc_info`
   （原异常对象），事件才有真实类型与调用帧（BUG-18）；quiet 作用域
   内**所有**主记录者（含内层清理）按 `quiet_generation_scope()` 标
   `committed_side_effect_failed`（BUG-10）。
11. **稳定密钥身份（TASK-02）**：`GATEWAY_KEY_REF_SECRET`（≥32 字节
   方为就绪）只用于 HMAC-SHA-256 计算 `key_ref`（`kh1-` + 32 hex），
   纳入 `_CONFIGURED_SECRET_ATTRS` 掩码，永不进入日志/平台输出/构建
   产物；秘密缺失/过短时标识明确不可用（`key_ref_ready=false`、事件
   `key_ref` 为空），**禁止**用真实密钥、普通哈希或随机盐兜底。凭证
   身份在实际 HTTP/SDK 调用边界经 `credential_scope(role, provider,
   api_key)` 绑定（chat/analysis/continuity/rumination；反刍按
   `_model_config()` 实际生效 Key 回退归属）；穿越边界的异常被标注
   `gateway_credential` 供边界外捕获点归属。事件携带
   `key_ref`/`credential_role`/`provider`；fingerprint **仅在有标识时**
   追加密钥身份——无凭证/历史未知事件保持旧公式指纹（不与已识别密钥
   混组、不拆旧组）。页面短标识 `K-` + 8 位（相撞延长显示），聚合与
   筛选始终用完整 `key_ref`。
12. **密钥按需查看（TASK-01）**：`gateway/credential_api.py` 白名单
   固定（UPSTREAM/ANALYSIS/CONTINUITY/反刍实际生效 Key + 三个插件
   Token）；Supabase 服务端 Key、数据库密码、标识秘密、GATEWAY_TOKEN
   不进白名单。元数据接口绝无真实值；reveal 按项返回、
   `Cache-Control: no-store`、鉴权 fail-closed（未配置 token 拒绝）。
   前端初始只取元数据，真实值用文本节点写入，隐藏/离开/重进清理并
   取消在途请求；不写浏览器存储。真实查看是白名单专用例外，不得
   扩大到日志、普通状态/错误响应、业务表或构建产物。

## 维护方法

- **新增故障路径**：先查该路径是否已有日志；无则补（优先普通 log，
  需要模块/操作/结果语义时用 evt extra 或 emit_error）；返回 5xx 的
  分支至少要有一条 WARNING+ 日志，否则依赖中间件兜底（事件缺上下文）。
- **新增管理 API 模块**：在 `_LOGGER_MODULE_RULES` /
  `_ROUTE_MODULE_RULES` / `_MODULE_LOGGER` / 前端 `MODULE_LABELS` /
  `_CODE_MESSAGE_ZH` 五处同步登记模块名。
- **新增模型调用边界**：用 `credential_scope(role, provider_label(base_url),
  api_key)` 包裹实际 HTTP 调用与其异常包装；回退链（如反刍→CONTINUITY）
  必须解析实际生效 Key 后再进作用域。
- **新增脱敏形态**：优先扩 `_BODY_VALUE_PATTERNS`（引号形态：受限贪婪，
  不得越过帧边界）或括号形态的配对扫描参数；持久化、平台输出与错误
  出口自动共用。改 `_PlatformScrubFilter` 时不得碰 `record.exc_info`
  （BUG-20 契约）；改异常副本时必须保留链元数据与 ExceptionGroup 子
  异常（BUG-21 契约）。
- **查询性能**：列表是查询时 GROUP BY；事件量增大时优先调
  `GATEWAY_LOG_MIN_LEVEL` / 保留期，必要时才考虑汇总表（须保持次数
  准确与 cursor 稳定语义）。
- **排障**：日志页 meta 的采集状态（队列/丢弃/最近写入/spool/清理/
  累计损坏损失/密钥标识就绪）是第一入口；writer 故障看平台日志
  `gateway.log_internal`（限频 60s）。

## 已知风险与边界

- spool 默认关闭：数据库故障期间进程重启丢事件（dropped 计数可见），
  不承诺跨容器重建保留；启用需确认持久盘。spool 容量上限覆盖
  `.jsonl` 与 `.jsonl.corrupt`（BUG-14），损坏文件数与事件丢弃数
  分开报告、累计口径展示（BUG-15）；删除失败按实物核算、写入前预留
  额度（BUG-22）；本地保留期与数据库共用配置（BUG-24），损坏文件
  TTL 以 mtime 为近似锚。
- 平台输出脱敏覆盖 root + uvicorn 命名 logger 的**标准 Formatter**
  handler（`record.exc_text` 缓存）；自行格式化 `exc_info` 且不读
  `exc_text` 的非标准 handler 仍可能输出原始帧文本——持久化侧不受
  影响（`scrub_text` 兜底）。Docker 容器内端到端未验证（本机无
  docker）；`.dockerignore` 已排除凭证材料，镜像层验收待条件具备
  （BUG-28）。
- 结构化 SDK 错误只保留 code + message 模板行；已知 message 回显形态
  （22P02 / malformed array literal / 跨行 row / key）按模板剥离输入值
  （嵌套括号 / 内嵌引号由配对扫描与受限贪婪处理），上游新回显形态需
  扩 `_BODY_VALUE_PATTERNS`（明确边界）。
- `uvicorn.*` / `asyncio` 不采集：ASGI 层未处理异常由中间件记录；
  Python 启动前 / 进程被杀只能查平台日志。
- 4xx 预期拒绝按 WARNING 记录（上游 4xx 记 degraded），高频预期拒绝
  依赖队列上限防放大；如出现日志放大攻击迹象，调高 `_MIN_LEVEL`。
- 查询时聚合在大事件量下成本上升（索引：occurred / module+level /
  fingerprint / level / request_id / key_ref）；30 天默认保留控制规模。
  已看集合 cursor 随翻页增长（每页 ≤50 fingerprint），API 侧 1000 上限
  兜底，超出按 400 引导刷新。
- `X-Request-ID` 由服务端生成（客户端提供的同名头不信任）；请求 ID
  与创建幂等键是两个概念，不得混用。
- 密钥标识依赖 `GATEWAY_KEY_REF_SECRET` 注入：缺失/过短时事件
  `key_ref` 为空（与未关联/历史未知同口径显示）、配置页与日志页提示
  未就绪；多实例须注入同一秘密，轮换标识秘密会改变全部身份（需显式
  版本边界）。TASK-01 复用 `GATEWAY_TOKEN` 的单用户前提：存在其他
  普通调用者时必须先增加独立管理凭证。
