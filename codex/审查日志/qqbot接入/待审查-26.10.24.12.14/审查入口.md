## 已实现的规则

| 情况 | 行为 |
| --- | --- |
| 正常判断不发送 | 等10、20、40、60分钟，此后每小时；不造聊天记录 |
| 连续错误 | 第1～4次后等5分钟、15分钟、1小时、2小时，第5次停止 |
| HTTP 401／403 | 立即停止；HTTP 429遵守更长Retry-After |
| 等待起点 | 模型结束时，且不能短于配置基础间隔；保留所有原资格检查 |
| 新私聊／QQ恢复命令／切换开关／重启 | 不能解除已持久化的故障停止；普通私聊可用 |
| 配置页恢复调用 | 按显示的故障版本恢复；保留开关、主人暂停／当日静默、每日额度和最近故障历史，等待基础间隔 |
| 取消或迟到结果 | 不记模型故障，不应用旧主人修订号的结果 |
| 异常重启的在途评估 | 计一次中断故障，退避后再试；若为第5次则停止 |
| 日志 | QQBot模块，复用现有handler／队列／writer；全局采集关闭则不采集，不补录 |

没有新增AI每日评估次数上限；每日30条仍为实际主动消息额度，原上限输入保持。没有SQL、远端存储结构或环境变量变化。一次主动模型调用仍同时判断发送与生成内容。

## 重点审查路径

1. `gateway/qqbot_proactive.py`的分类／退避／状态校验，以及`qqbot_store.py`中begin、finish、recover、resume的事务边界、租约、修订号和故障代次。确认失败与静默不能互相意外清除、恢复不能清额度。
2. `gateway/qqbot.py`的调用完成后计时、取消／迟到结果、持久化失败后的停止、发送前复核，以及私聊、回执、原文同步路径是否保留。
3. `gateway/qqbot_settings.py`的严格POST载荷／鉴权／设置锁、409冲突和503存储失败；QQ关闭不为读取评估状态创建账本。
4. `admin/js/pages/config.js`的恢复按钮／状态显示、共享保存锁、失败回读、旧挂载返回隔离；`logs.js`的QQBot标签及缓存版本。
5. `gateway/logging_events.py`及`qqbot_model.py`的模块归类、真实异常、密钥作用域及HTTP正文排除。采集关闭不能影响故障计数，也不能绕过总开关单独写入。

本地存储彻底不可写时，只能保证当前进程停止；强制终止后的状态以最后成功保存的记录为准。损坏评估记录不会被自动清空，需先修复存储。此限制已明确记录，不把进程内变量当成已落盘停止。页面无新增轮询，进入、刷新或操作后显示新状态。
