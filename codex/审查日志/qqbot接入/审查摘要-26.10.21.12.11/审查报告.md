## 功能与执行链核对

R9预期为：明确未提交的主动问候只有在主人状态与生成版本仍有效时才能重新投递；暂停、当日静默、新输入或过期使旧任务失效，重启或恢复开关不能使其复活。已提交confirmed/unknown继续按实际结果补记，不能误撤销或重复投递；普通回复和控制确认保持可用。

核对完整链路：生成时持久化eligibility_revision → NotSubmitted及回执日志 → 恢复时资格复核 → queued认领事务 → 运行器提交前检查 → OneBot取得write_lock后再次检查 → socket写出 → confirmed/unknown结果落库。

关键实现检查：

- `qqbot_store.py:60-62,222-232`：旧账本自动补资格列，主动任务保存生成版本；无法还原版本的旧未提交任务保守淘汰。
- `qqbot_store.py:275-293`：共用过期、修订号、暂停、当日静默和待处理输入校验，已处理完的新问题仍通过修订号使旧问候失效。
- `qqbot_store.py:259-273,330-334`：恢复和认领都复核；无效任务failed并清除载荷，认领继续处理后续普通回复。
- `qqbot.py:203-214,251-295`：生成和提交共用时段、安静期、每日额度/冷却判断，区分SendCancelled与可重试NotSubmitted，并检查租约和在线状态。
- `qqbot_transport.py:50-57,72-76`：取得写锁后、writing=true及send_json之前再次调用同步资格检查；握手API不误调用发送任务检查。
- 取消资格只影响未提交路径；confirmed/unknown不套用queued恢复取消规则，保留真实历史及不重发约束。

## 逐项复验

R9原三个独立失败场景均通过：暂停、今天静默、普通新输入到达期间的queued补记失败，恢复后均不发送旧问候。

本轮实际执行23项新增永久边界，覆盖：

| 边界 | 结果 |
| --- | --- |
| 暂停后恢复、当日静默后恢复 | 版本改变后旧问候不复活，控制确认正常发送 |
| 新输入已生成回复、pending已清空 | 仍凭持久版本淘汰旧问候，只发送正常答案 |
| 三种主人变化后停止并重启 | 已保存资格持续生效，旧问候不恢复 |
| 日志本身写入失败、仅保留进程缓存 | 数据库恢复后仍按最新修订号淘汰失效任务 |
| 恢复晚于TTL、协议离线 | 用恢复时当前时间淘汰，重连不补发 |
| 状态未变的合法NotSubmitted、含重启 | 允许安全重试，仅一次真实投递/结算 |
| confirmed/unknown补记期间主人暂停或发来新输入 | 实际结果如实补记、不重发；unknown不伪造assistant历史 |
| 真正OneBot写锁等待期间暂停、新问题已处理完 | 取得锁后拒绝，socket零动作帧 |
| 等锁期间过期、时段/服务器开关/安静期/额度变化 | 真正写出前拒绝，清载荷且不多计主动次数 |
| 已进入socket写出后收到暂停 | confirmed/unknown按实际回执结算，不假称已撤回 |
| 旧写者恢复无效queued、旧账本没有版本 | 认领再次淘汰；已提交成功仍能记录历史 |
