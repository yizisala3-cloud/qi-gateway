# 光遇聊天接入 · MuMu 设备 10

本机用 ADB 截图、RapidOCR 读屏，UI Automator2 读取游戏原生编辑框，MuMu 官方 CLI 输入中文。文字推理由 `https://yiziwanguan.com/v1/sky/chat/completions` 预览接口完成，沿用现有网关人设和记忆；游戏确认发送后，再调用 `/v1/sky/deliveries` 保存正式对话。基础交付协议此前已上线；本轮新增开关和原归属补交修复仍是本地候选，发布状态见[统一当前状态](../../codex/网关当前状态/网关当前状态.md)。只读取根目录 `.env` 的 `GATEWAY_TOKEN`，不在本工具复制密钥。

当前实现文字聊天和画面理解，不执行移动、抱抱、牵手、购买或其它游戏动作。本机已开启**群聊模式**，自动接收聊天面板中所有能显示名字的玩家；主要用户仍为“叶子”，其他玩家保留各自身份。回复发到游戏当前聊天频道。

## 日常使用

1. 启动 **MuMu安卓设备-10**，进入光遇。与群聊玩家位于能够聊天的场景，展开左侧聊天记录，保持能看到 `消息 - 玩家名`。输入栏保持空白。
2. 双击桌面“启动光遇AI”快捷方式，或本目录 `start.cmd`，保留启动窗口。启动时屏幕已有文字作为基线，不补答旧消息。
3. 任意带名字的玩家发新的短文字。连续两次读到后交给模型判断；多条消息合为一条自然短回复，最多 35 字，先回应最后一条，较早内容只在仍相关时兼顾。叶子仍是主要用户，旧发言不能盖过最新内容。不要同时操作设备 10 的聊天输入框。
4. 双击 `stop.cmd` 停止，或在启动窗口按 Ctrl+C。正在进行的 OCR／模型请求结束后退出，发送前会再检查停止标记。再次双击 `start.cmd` 可重新启动。

备注名用于筛选触发消息，并不会把游戏公共聊天变成私聊。需要保持设备与聊天记录面板打开；切到其它 Android 应用、分辨率变化、草稿非空、输入不一致或发送回显不明确时程序停止，不盲目重试。

## 配置与诊断

`private/config.json` 是本机配置，缺失时从 `config.example.json` 创建。当前已校准设备 10 的 1600×900 横屏画面；ADB 端口从 MuMu CLI 实时获取，并复核编号和设备名。其它设备不会自动接管。

`chat_mode="group"` 接所有带名字的玩家，`primary_user="叶子"` 保留主要用户身份，不把其他人的话或关系套给叶子；`chat_mode="direct"` 则只接 `peer_names` 白名单。示例配置保留 direct 默认，本机私人配置已切换 group。修改配置后停止并重启生效。

低延迟版使用常驻 OCR 子进程、原始图像截图和分区域识别，每 1 秒轮询一次；没有新消息时不调用模型。OCR 使用单线程模型会话，避免额外线程在截图间等待工作时占用 CPU。同一张 14 行消息截图、每秒识别一次的 6 轮对照中，CPU 耗时从 10.703 秒降至 4.406 秒，约减少 59%；单次 OCR 中位数从 439 毫秒增至 743 毫秒，文字结果相同。此数值不含模拟器负载，不表示风扇或温度测量。实际对话仍包含模型生成、输入及游戏回显等待，详见 `private/last_latency.json` 的逐段计时。

收件线程在模型生成和键盘准备期间继续读屏；准备按发送键前还会补读聊天区域。若有新消息，作废未发送草稿，合并后重新生成，以最新内容为主；已输入时仅清除文字仍逐字匹配的本程序草稿，用户改过的草稿保留并停止。作废草稿不进入对话历史或正式云端记录。每次发送最多更新两次草稿，之后及实际提交／回显期间的新消息留下一轮。末尾陌生人不覆盖具名消息，重启不自动重放旧队列。

同次运行按玩家身份及规范化消息去重：统一排版和引号，末尾纯标点颜文字的 `（）`、`（‘）`、`（’）` 视为同一句，原文仍交给模型。保留数字、否定词、运算符、问号和有意义的 emoji，不模糊合并玩家身份。Inbox 对待处理、处理中及已处理事件再次去重。合并顺序优先采用最后可见屏幕的行序，避免 OCR 较晚识别的旧句变成“最新”。

每条收件事件有本机 ID，每批回复有触发事件导出的决定 ID，交付时复用同一 ID。`private/decisions/` 记录生成、准备、提交前、等待回显、游戏确认、完成／PASS和失败状态；旧草稿为 `superseded`，指向新决定。同一批已存在的决定拒绝再次生成或发送；不同事件可以回复相同文字。本次不启用主动消息或定时器。

模型完整输出 `PASS`（忽略大小写和首尾空白）表示本轮保持沉默，程序不会输入、按发送键或把 PASS 发进游戏。跳过后只确认处理当前批次，新来的消息仍保留；后续点名或提问可以正常回复。这是逐轮语义判断，没有新增固定冷却时间。`private/last_reply.json` 的 `action=pass`、`handled=true`、`sent=false` 表示已跳过，`action=reply`、`sent=true` 表示已确认发送；上一次 `last_send.json` 不会因为跳过而被伪造成新发送。

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\sky_companion\bridge.py doctor
.\.venv\Scripts\python.exe -X utf8 tools\sky_companion\bridge.py read
.\.venv\Scripts\python.exe -X utf8 tools\sky_companion\bridge.py calibrate
.\.venv\Scripts\python.exe -X utf8 tools\sky_companion\bridge.py ask --text '在吗'
.\.venv\Scripts\python.exe -X utf8 tools\sky_companion\bridge.py stop
```

`ask` 只调用 AI 并保存预览，不发到游戏。诊断、校准、发送和自动循环共享设备锁；先停止自动循环再执行诊断或校准。新安装环境用 `.venv\Scripts\python.exe -m pip install -r tools\sky_companion\requirements.txt` 安装本机依赖，不需要把这些依赖部署到网关。

生成阶段不保存正式 user/assistant 对话；PASS、过长输出、草稿冲突、停止或回显未确认也不会交付入库。发送成功后，带唯一 UUID 的记录先落到本机 `private/deliveries/`，再交付网关。数据库在一个事务中保存双方消息和幂等回执；相同 UUID、相同内容的重试返回原消息 ID，内容冲突会拒绝。若游戏已确认但入库响应丢失，程序停止；重启只补交该记录，不重发游戏文字。不得删除尚未 `persisted=true` 的交付文件。旧版已经写入的历史内容未自动清理。

部署依赖为 `gateway/main.py`、`gateway/sky_delivery.py` 和 `supabase/migrations/20261023010000_sky_confirmed_chat_delivery.sql`。先执行并核验兼容 SQL，再发布网关，最后启动本机；`/status` 应返回 `sky_delivery_protocol=1`。旧网关不支持预览路由时停止，不降级调用会提前保存对话的普通接口。

重新校准时先展开聊天记录，再依次点记录区域左上、右下、聊天入口。记录区域必须排除底部输入框。校准仅保存坐标，不发送消息。`send_button=null` 使用本设备实测有效的回车发送。

日志为 `private/bridge.log`，最新读屏为 `private/last_read.json` 和 `private/screen.rgba`；诊断或发送确认时额外生成 `private/screen.png`。成员为 `group_members.json`，队列及事件状态为 `inbox.json`，回复决定为 `decisions/`，交付为 `deliveries/`；`last_reply.json` 含决定 ID、触发 ID、合并条数及草稿更新次数。成功回显为 `last_send.json`，发送尝试为 `last_send_attempt.json`。日志 `reply_decision_started/finished`、`reply_draft_superseded` 和 `model_passed` 可定位具体轮次。这些文件都在已忽略 Git 的 `private/` 中，可能含真实聊天；OCR原始截图保留本机；开启视觉后偶尔上传压缩的游戏画面到同一授权网关，不读取其它应用画面。

## 识别边界

- OCR 置信度不足 0.85、没有明确发送者分隔符、陌生人或记录区域外的文字不触发。群聊要求实际游戏的 `文字 - 名字` 后缀及深色聊天气泡，不将自己浅色气泡中的名字或标签当成新玩家。direct 模式也优先校验实际发送者后缀，正文中的“叶子：”不能绕过身份筛选。玩家首次复述 AI 的话可以触发。
- 游戏面板没有可读消息 ID。本机 ID 不是游戏原生 ID；同次运行，同一玩家规范化后的同句只处理一次，不同玩家分别保留。只改末尾纯标点颜文字的真实重发也可能被合并；不承诺消除所有汉字／名字 OCR 错误。重新启动仍建立新基线。
- 在可见聊天 ROI 内，按同一深色气泡的完整发送者边界累积正文，不固定为两行；名字可以在正文之后的末行，横杠可在正文末尾或名字行。OCR 与解析共用布局规则，先合并同排碎片，再用文字中心距离处理表情／粗体导致的文字框重叠。名字复读须与原身份和位置一致、置信度至少 0.85；正文末尾小横杠可单独重读验证，不能借此改正文。重读根据可见气泡边界排除外部背景，不按配置猜名字。不同气泡、明显行距或左侧不符不能借名。表情、裁切、遮挡、低置信度和不规则布局仍可能漏读，OCR 不保证逐字无误。
- 点击发送后必须同时确认草稿清空和画面出现新增自身回显。按实际五秒截止时间只读轮询，发送键只按一次；已经开始的一次 OCR 可能在截止后才完成。旧同文滚出、底部出现新同文可结合气泡来源和位置确认；回到同位置时还要求前置序列整体被多条新具名消息替换。只有旧回显、其他玩家复述、单行改变或完全无可观察变化时不能确认。失败停止，不自动重发，人工核对后再恢复。不要同时滚动聊天历史。
- 空白和草稿从游戏当前聚焦的原生 EditText 读取，提示文字必须完整相等才视为空；输入后要求原生文字与待发送文字逐字一致。不会把透明输入框后面的游戏提示误判为草稿。UI Automator2 按需在设备 10 启动本地服务，读取失败时停止。
- 发送回显区域延伸至实际原生编辑框上沿，自身气泡额外用 2 倍裁剪重读，支持拆行合并。回显统一全半角、弯／直引号和末尾标点；明确的自身气泡在目标不少于 12 字时最多容忍一处 OCR 编辑差异，短于 12 字严格匹配；无来源的兼容数据仍需不少于 16 字才允许一处差异。原生输入始终逐字核验，不因回显容错而放宽。OCR 不保证逐字无误。
- 新协议隔离的是正式对话入库；预览仍正常执行人设、记忆检索及原有检索日志行为。既有缺陷与逐项复验见[活动清单](../../codex/需求/光遇接入/后续待修复.md)。
- 符号名字、批次预算、助手变化补交及OCR缺行排序已完成本地修复和隔离验证；配套迁移已于2026-10-24执行核验，服务发布与实机专项仍分别记录。其它活动条目仍按清单保留，不能以回归全绿认定全部群聊场景已验收。
- 首次取批及草稿合并都不越过 20000 字符请求预算，放不下的新增事件保留；单条超限隔离保存，其他消息继续。JSON 状态只对 Windows 替换错误 5/32 最多尝试四次、间隔 50 毫秒，持续失败停止；不重试游戏发送。
- 本工具未验证教程中的互动坐标，也没有实现避开游戏检测的行为。

## 画面理解

`vision={"enabled":true,"every_turns":4,"max_age_seconds":60}` 开启现有模型看图，本机已开启，示例默认关闭。首个新消息轮看图，之后每四个已完成回复／PASS轮或观察超过六十秒时，在下一次收到新消息后更新。模型也可输出内部 LOOK 请求新画面；空闲不上传，不新增后台模型。游戏截图压成最长边1280的JPEG、上限500KB，经同一预览接口发送；后续文字轮复用有时间的摘要。看图用低思考强度及2048预算，缓存文字轮快速生成。看图耗时仍需另加输入与游戏回显时间。

能看清时正常按人设接话；测试中看不到／看不清就如实说，角色身份不能凭外观确认。非测试日常缺图允许简单想象，保持原聊天效果；想象不能写入事实观察摘要。看图失败保留文字通道，后续一分钟内不再请求图片；设备绑定／前台异常仍停止。LOOK、JSON、图片与scene不作为正式游戏聊天交付，只交付确认发送的自然回复。

`private/vision-last.jpg` 为最新压缩截图，`last_vision.json` 记录时间、大小、状态和摘要；错误只记结束原因、长度及用量，不保存思考过程。`vision_updated` 可定位刷新轮次。模型预览不等于游戏已发，启用后需在聊天记录可见时核对新消息的实际回复。

## 配置页开关与确定交付恢复

新版本在配置页提供光遇接入总开关，使用已有app_settings的sky.enabled行保存enabled和pause_epoch，默认关闭。status声明sky_access_control=2，本机GET /v1/sky/settings读取状态。模型预览带X-Sky-Access-Protocol: 2，旧客户端请求新版预览会被426拒绝；本机读不到有效暂停代次时停止，不以旧布尔返回值代替。管理接口GET/PUT /admin/api/sky/settings仍只提交严格布尔enabled，需原网关鉴权；不另发或复制真实Token。

每次成功关闭通过数据库事务生成新的pause_epoch，开启保留该值。即使在一次模型请求内快速关后再开，旧草稿也会取消，期间收件作废；重开建立新基线，之后的新消息正常处理。收件线程在模型等待期间检查状态，生成、看图、PASS完成、输入及提交边界核对本批代次；取消时只清掉仍逐字匹配的本程序草稿。已经提交的消息继续确认并保存，关闭不阻断已发送记录的补交。开关无法确认则拒绝输入／发送；本机连接程序仍需运行，配置页不能代替Windows进程启动器。

旧模型请求迟到的sky_disabled／sky_generation_cancelled只取消该请求，不能改写当前开关缓存或清掉重开后的消息。处理时强制回读当前设置；只有权威状态或代次变化才全局暂停，否则按原事件ID取消该批。当前状态读取失败则保留队列并停止。视觉成功观察及失败退避的权限检查、状态和诊断写入共用锁，暂停后的新缓存不会被旧结果恢复。

首次取批和合并都按实际JSON／文字请求的20000字符预算拆分，剩余事件保留。单条超限保存到private/rejected_messages并标记，其他消息继续处理，不截断原文。缺行保留已知相对顺序，模糊名字不授予主用户身份；名字末尾点号属于身份的一部分。OCR同排拼接、局部重读及多行合并保留自动插入空格的位置，不能把排版空格当姓名边界；多个同等可信分隔符拒绝识别，独立姓名末行的几何边界保留完整名字。

新增自身回显确认后，先保存确定交付载荷和决定中的confirmed_at，再保存辅助截图／JSON。last_send等只作辅助诊断；若它写失败，确定载荷仍能在下次启动补交。outbox缺失但有明确game_confirmed／record_pending决定及确认时间时可重建；只有submitting／awaiting_receipt且没有确定outbox时不可自动当成功。补交保持原UUID、正文和确认时刻，不重发游戏消息。
